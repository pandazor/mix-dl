# dl-manager 0.4.0 — conception

Demande : trois commits distincts (licence AGPLv3 ; génération guidée des tokens Tumblr/DeviantArt ; sites personnalisés nommés), puis paquets Windows/Linux 0.4.0. Le téléchargement DeviantArt vient d'être validé par l'utilisateur.

## Choix
- AGPL-3.0-only pour le code propre, texte LICENSE inclus dans les archives ; licences tierces conservées.
- OAuth : envelopper la commande gallery-dl déjà utilisée avec succès. Refaire les protocoles en Go dupliquerait les moteurs ; afficher seulement une commande laisserait le copier-coller demandé à supprimer. Bouton Générer le token, avertissement de connexion manuelle, autorisation dans le navigateur habituel, champs secrets remplis automatiquement puis Enregistrer reste explicite.
- Sites : nom + domaine, identifiant interne stable custom_<32 hex>. La détection par domaine évite un choix manuel à chaque ajout. Domaines existants intégrés réservés, pas d'URL libre utilisée comme commande ou d'extracteur Python saisi. Le moteur gallery-dl reste responsable de la compatibilité.

## OAuth
Un service par application, une connexion à la fois (callback gallery-dl sur localhost:6414), expiration 5 minutes, annulation et arrêt à la fermeture. Commande sans shell ; processus masqué/contrôlé avec internal/process ; désactiver cache OAuth et toute configuration externe. Configuration temporaire privée, aucun token dans les arguments, journaux, SQLite ou fichier de sortie. Les sorties sont analysées en mémoire et bornées. Seule une URL HTTPS d'autorisation au chemin attendu du site sélectionné peut être ouverte. Les erreurs sont des messages fixes sans sortie brute.
Endpoints POST protégés par X-DL-Token : oauth/start {site}, oauth/status {id}, oauth/result {id} (lecture unique des nouveaux tokens), oauth/cancel {id}. Les secrets ne figurent jamais dans GET /api/state ni dans status. Quitter ferme service et enfants. Fermer le dialogue annule/efface les champs ; réponse tardive ignorée.
Le service réutilise les flux OAuth de gallery-dl, y compris sa page de redirection DeviantArt. Le mot de passe du site n'est jamais demandé par dl-manager. La clé Tumblr partagée et son quota restent inchangés.

## Sites personnalisés
Settings.CustomSites map ID -> {name,domain}, persistée dans le JSON existant (pas de migration destructive). Nom obligatoire <=100 caractères, domaine DNS ASCII/punycode normalisé en minuscules, sans chemin/port/identifiants, >=2 labels. Unicité du domaine ; correspondance exacte ou sous-domaine avec frontière point, domaine le plus spécifique prioritaire. Les sites intégrés gagnent toujours.
Créer/renommer via API dédiée sous verrou du gestionnaire ; domaine immuable après création pour ne pas réaffecter un compte à un autre hôte. Suppression seulement si aucune tâche ni compte ne référence le site. Les sauvegardes incluent les définitions, paramètres et comptes des sites personnalisés ; import remappe les IDs et fusionne par domaine, sans changer les existants sauf remplacement explicite. Anciennes sauvegardes v1 lisibles ; document interne v2 pour l'export avec définitions personnalisées, enveloppe chiffrée inchangée.
Une fiche est ajoutée à Comptes & sites ; connexion cookies et paramètres actuels. Validation du domaine des cookies. Dossier site basé sur le domaine stable (pas le nom renommable), puis métadonnées génériques de créateur lorsque disponibles. Les tâches commencées conservent leur destination et identité. Le groupe Autres sites reste le fallback.

## Validation et limites
Tests OAuth avec un processus local de test : sortie fragmentée, jeton unique/paire, URL hostile, sortie malformée, échec/refus, délai, annulation, fermeture, concurrence, lecture unique et absence de fuite via API/logs. Aucun vrai login ni téléchargement distant lancé par les tests.
Tests sites : domaines trompeurs/dupliqués, noms Unicode/HTML, persistance/reprise, héritage global/site, comptes isolés, dossiers sûrs, export/import et v1. Chrome contrôle les vrais parcours avec simulation limitée au fournisseur OAuth externe et au sélecteur OS.
Suite Windows, TypeScript, vet et builds Windows/Linux ; paquets vérifiés. Les limites de lancement graphique natif/Linux restent explicites. Ne jamais modifier l'instance utilisateur, ses données, téléchargements ou identifiants. Pas de publication/tag automatique, pas de push forcé.
